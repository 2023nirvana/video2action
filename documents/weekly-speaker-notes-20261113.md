主线约10分钟，含两段短视频；另附约2分钟视觉延迟说明，跨来源案例说明可随视频穿插。汇报围绕“把真人与机器人视频接入同一可执行命令接口，并用执行状态保留动作事件”组织。主要数字、比较协议与延迟记录见[本周公开结果数据](../data/weekly-progress-20261113.json)。

## 8–12分钟讲稿

### 0:00–0:55｜本周推进了什么

前面我们已经建立了从视频到机器人命令的基本路线。这周重点解决两个问题：第一，真人视频和机器人视频能不能使用同一个运动入口；第二，进入这个接口以后，视频里真正重要的动作事件能不能被执行出来。

最清楚的进展是共同GV前端：在相同数据、相同更新次数的实验里，它改善了机器人视频输入的执行质量；这一能力也已经扩展到了256段训练来源。与此同时，我们把系统比较、共享机制和困难动作分开验证，因此现在可以更具体地说清楚：哪些收益来自整条系统，哪些机制已经得到支持，以及接下来应该优化哪一层。

### 0:55–2:20｜共同pipeline：共享的到底是什么

先看这张主流程图。真人视频和机器人视频都先经过冻结的GVHMR视觉估计。机器人这里输入的是渲染RGB：先做人体检测与跟踪，正常路径会补齐漏检帧；整条检测提取失败时，再尝试只依赖RGB的整帧裁剪。没有读取仿真的机器人关节角，也没有用teacher的框替代检测。

裁剪以后，ViTPose提供二维关键点，HMR2提供图像特征，再由GV估计三维运动。我们把结果整理成145维，包括身体旋转、根部运动、相对根旋转和静止概率。对于机器人，这个表示是人体估计器从机器人外观得到的运动代理，不是G1的29个关节测量。

两个域的145维序列进入同一个轻量时序MotionEncoder，得到128维表示，再通过共同命令头每100毫秒预测五个控制时刻的命令，每个控制项持续20毫秒，对应50Hz低层控制。可选的RGB小残差复用GV已经提取的1024维图像特征，在128维表示上做修正。随后经过一次FSQ量化，形成SONIC的64维命令，冻结的SONIC控制器结合实际本体状态输出29维动作，驱动G1。

这里训练的是运动映射、共同命令头和小残差，GV及低层SONIC都冻结。低层本来就有状态反馈，但本周主系统还不是完整的高层在线闭环：GV读取整段视频，运动窗口也包含半秒未来信息。因此它现在证明的是离线视频到可执行命令的共同接口。

### 2:20–3:35｜证据一：32段、同6k更新的严格对照

为了判断共同前端本身有没有价值，我们先固定32段训练数据、同一个父模型、同一个采样表以及6000次更新，比较旧分域路线、共同GV和共同GV加RGB残差。

在机器人输入的DEV12上，root XY误差从0.382米降到0.247米，加RGB残差后进一步到0.231米；关节误差从0.120降到0.097，再到0.096弧度。共同GV带来的主要收益比RGB小残差更大。配对到每个动作看，GV的关节误差在12条里改善了11条。

这组结果支持的是：把机器人RGB先转换成与真人兼容的运动代理，可以改善机器人视频到命令的映射。它没有证明真人域同步全面提升；同一组里，真人root XY从0.262升到0.304米，加入残差后是0.301米。因此当前明确成立的是机器人域受益和共同入口可用，真人迁移收益要单独验证。

这一页若播放三路walking，请使用同32段、同6k的三路视频；后面256段的新旧系统视频属于另一组比较。

### 3:35–4:55｜证据二：256段后的双域系统比较

扩到256段以后，我们用预先定义的真人DEV准则，各选出一套旧系统和共同GV系统，再在相同DEV12和VAL43上评估两种输入域。这是完整系统的比较，包含了各自训练历史、步数和残差选择的差异。

机器人DEV的XY误差从0.411米降到0.181米，全局MPJPE从484毫米降到208毫米；机器人VAL的XY从0.0517降到0.0436米。真人DEV也改善，但真人VAL的XY从0.0304升到0.0392米，全局MPJPE从46升到55毫米。这张表显示了共同系统最明确的改善方向，也保留了真人短片上的回退。

这里不能把0.18米和0.04米直接看成模型进步的先后阶段：DEV平均评分6.96秒，以移动动作为主；VAL平均3.03秒，包含较多短时上肢和静态动作。每个集合内部的新旧配对才是有效比较。

现在播放固定世界相机的walking上下对照。它直观展示机器人域的轨迹差别；这只是一个案例，整体结论仍由刚才的12条和43条配对结果支撑。

### 4:55–6:10｜证据三：共享与scale，分别回答两个问题

共同GV有效以后，另一个问题是两域是否必须共享同一组MotionEncoder权重。我们固定同一个联合父模型、同一采样和共同命令头，做共享与复制成两个编码器的两seed续训对照。共享模型的可训练参数是54.2万，独立编码器是97.7万，参数少44.45%。

精度上，共享还没有显示优势：真人VAL的XY是0.0335对0.0318米，独立编码器更低；机器人VAL是0.03714对0.03728米，两者接近，而且两个seed方向不一致。因此目前共享的价值是较小的参数规模和统一接口，不把完整系统的改善归因成“共享权重必然更准”。

再看规模：同seed、同24k更新、无RGB残差，48、128、256段训练的真人VAL关节误差依次为0.1198、0.1075、0.0971弧度，显示了身体动作拟合随覆盖扩大而改善的趋势。但DEV位置与朝向并不单调。当前支持继续扩大动作覆盖，同时把运动事件和监督质量作为准入条件，而不是简单增加片段数就预期所有指标一起提升。

256段也不等于256次独立采集：它们来自27条原录制，teacher有效执行约17.4分钟。这是同一MoVi库存的扩展，不能描述成多场景大规模新数据。

### 6:10–7:35｜困难动作：为什么要评价事件

困难动作这部分回答的是更直接的问题：人跳了，机器人到底有没有跳？我们固定了8条真人动作，包含6条垂直跳或开合跳及2条踢腿，完成两域、两种初始化的32条学生轨迹。

关键发现是6条跳跃类动作中，teacher本身就没有出现持续至少50毫秒的有效腾空，学生也没有。也就是说，一部分动作事件在学生之前的参考到teacher执行链中已经丢失。如果继续只要求学生接近这个teacher，接触F1很高也可能只是双方都站在地面。

踢腿还说明了另一层问题：S66的teacher单腿支撑约2.12秒，真人输入学生只有0.77秒，机器人输入学生0.50秒，而且支撑时序也不一致。因此动态动作需要同时检查teacher能否完成，以及学生能否保留事件的幅度、持续时间与相位。

这8条真人视频合计38.3秒，真人学生播放并执行了完整输入；teacher因为需要0.9秒未来参考，合计有效支持30.86秒，覆盖约80.6%。没有监督的尾部继续展示，但不补造评分。可播放垂直跳初始化对照，看到“完整运行”和“正确完成跳跃”是两个不同问题。

### 7:35–9:05｜执行状态再查询：方向性进展

针对这个问题，我们用LAFAN补充了已经有机器人执行监督的困难窗口，从17个扩大到56个，来自19条独立训练录像、约732秒；验证集是另外5条录像的11个窗口。这一轮没有新增真人RGB。

三种方法分别是固定teacher状态的行为克隆、在student实际状态上重新查询命令并增加事件权重，以及额外提供仿真真实速度和接触的oracle。三组都固定训练三轮，比较最后一轮，避免事后挑最好的验证轮次。

按原录像等权，状态再查询相对BC把关节误差从0.312降到0.258弧度，去根平移MPJPE从91降到76毫米，接触F1从0.820到0.842。可以在15.5秒单腿demo里看到对应改进。相对初始模型，root收益对聚合方式敏感，所以当前更扎实的证据是姿态和支撑改善。

跳跃事件仍需要继续解决：固定7个teacher确有腾空的验证窗口，最终再查询的腾空IoU约0.061。加入仿真真实速度和接触也没有全面改善。这提示单纯多给状态信息不够，监督还需要告诉模型在当前状态下什么命令能真正恢复目标事件。这里的再查询主要调整当前yaw条件，还不是一个完整的状态纠偏专家。

### 9:05–10:00｜下一步的可检验假设

最后我们做了一个小型可达性探针：从3条TRAIN动作的6个真实偏离状态恢复完整仿真与控制器历史，测试78个合法token候选。预先固定的综合目标使平均关节误差降低约12%、根速度误差降低约10%，但XY误差增加约2.3%。所以冻结的命令接口里存在局部改善空间，同时不同执行目标之间确实有权衡。

接下来最值得验证的假设是：先保证teacher保留目标动作事件，再从真实student状态寻找可执行的纠偏命令，把这些命令蒸馏到共享视频接口。我们已经有共同前端的严格对照、256段双域系统评估和状态再查询的方向性证据；下一步的实验就围绕事件保真与实际纠偏能否改善未见动作来展开。

## 补充讲稿：视觉计算、控制频率与在线跟随（约2分钟）

这一页把部署效率拆成三个层次。共同接口的目标是每100毫秒更新一次视觉命令，每次给出五个20毫秒控制项，因此新视觉命令目标为10Hz，SONIC低层控制为50Hz，PD与物理为200Hz。这三种频率描述不同环节；低层能够50Hz执行，并不代表摄像头画面能够50Hz完成理解。

这周已经测了常驻完整视觉前端。模型只初始化一次，新到达RGB只编码一次，计时包含视频增量解码、检测、裁剪、关键点与图像编码、GV预测和后处理，以及运动特征的坐标接续。在同一张A40上，真人、机器人和网球三类输入的六种设置，服务时间中位数为0.624到0.647秒，P95为0.634到0.667秒。倒数对应串行服务能力约1.6次每秒，说明当前需要重点优化视觉端才能达到100毫秒更新预算。

这个0.63秒没有包括命令头、FSQ、SONIC、PD和机器人实际动作；模型初始化也另计。实验用静态相机假设下的文件回放，还没有测完整摄像头RGB到机器人首次动作的统一时钟延迟。因此这里可以报告完整视觉前端的服务时间，完整执行链的延迟仍需测量。

另一项1080个真实RGB前缀实验，冷处理中位数为29.88秒。每个前缀都重新裁剪、启动进程并加载模型，前缀长度也不同。它回答的是冷启动前缀处理成本，与常驻每更新的0.63秒属于不同协议，不能相除得到系统加速倍数。

下一步计划是轻量逐帧视觉加GRU或因果TCN，使用过去窗口，每100毫秒产生五个控制项，再与真实机器人执行对时。这个流式视觉学生尚未实现；已经完成的过去窗口适配仍使用GV输出，不能替代流式学生的完成证据。

| 测量对象 | 已测结果 | 计时范围与用途 |
|---|---:|---|
| 常驻完整视觉前端，6种设置 | P50 624–647ms；P95 634–667ms | 解码至运动特征；不含命令与执行；同一A40、每项71次有效更新 |
| 每项模型初始化 | 11.68–12.61s | 单列启动成本，不混入常驻服务分位数 |

| 摄像头RGB到机器人首次实际动作 | 尚无统一实测 | 需要采集、排队、视觉、命令、控制和执行使用同一时钟 |

常驻原型每项输入8秒、30fps，每批3个新帧，先积累30帧，最多保留120帧即4秒上下文。0ms设置只提交当前可用端点；请求250ms设置在30fps下实际取7帧、约233ms前瞻。预转码、模型初始化与服务计时分列。这里的“约1.6Hz”是服务时间倒数估计，不是实时摄像头实测更新率；FIFO模拟的首次特征提交也不等于机器人首动作。

## 主pipeline图：节点与连线

主链：`真人RGB / 机器人RGB → 冻结视觉前处理 → 冻结GVHMR → 16×145运动窗口 → 共享MotionEncoder → 128D → 可选共享RGB特征残差 → 共享命令/intent头 → 5×64 pre-FSQ → 一次FSQ → SONIC64 + 实际proprio930 → 冻结SONIC decoder → action29 → PD/物理G1`。

侧链：`前处理HMR2图像特征1024D → 同窗口插值16点并平均 → 与128D拼接 → 1152→128→128 MLP → 0.1 tanh → 加到128D`。

训练监督虚线：`已有reference → 官方SONIC编码/teacher物理执行 → pre-FSQ命令监督 + 7D motion-intent监督`。这条虚线是训练标签来源，不应画成部署时读取teacher。机器人训练视频渲染teacher实际执行轨迹；因此它不自动等于真人原动作真值。

## 三种比较回答不同问题

## Q&A

**Q：GVHMR在人类上训练，为什么能输入机器人？**

A：它接收机器人RGB并输出人体运动代理，跨外观的有效性由最终配对执行实验验证。检测器仍有人体先验；最初44段机器人缓存中有27.26%的帧漏检后被离线插值补齐，不能称为已经获得准确机器人骨架。整帧fallback也是RGB-only，并未读取GT。数值收益支持它在当前固定场景、动作面板上的适用性。

**Q：RGB残差是不是重新训练一个大视觉模型？加在哪？**

A：复用冻结HMR2的1024D缓存，只训练164096参数MLP。它在MotionEncoder128D输出之后、共同LayerNorm与命令投影之前相加。原来的7D intent修正加在pre-FSQ命令上；R46实际状态残差也作用于pre-FSQ，但输入和训练方式不同。

**Q：145、128和64分别代表什么？为什么还有5？**

A：145是每帧估计运动特征，128是16帧窗口压缩后的学习表征；每个控制时刻输出一个64维SONIC命令，内部以2×32组织。一个10Hz视觉anchor预测5个50Hz控制时刻，形成5×64，不是5种动作或64个动作类别。物理/PD为200Hz。

**Q：既然两个编码器更准，为什么保留共享？**

A：共享使本轮可训练参数少44.45%，机器人VAL精度接近，提供了一个紧凑共同入口。当前结果不支持共享精度优势，也不证明机器人数据提升真人泛化；下一轮要检验不同事件覆盖、数据量和独立新域下的权衡。

**Q：256系统的改善能归因于共同前端吗？**

A：这张表是DEV选出的完整系统比较，父模型历史、追加更新数及RGB残差都不同。前端效果看同32段、同6k那组；权重共享效果看两seed共享/独立那组，三张表承担不同论证。

**Q：真人VAL为什么回退？还算泛化改善吗？**

A：真人VAL的XY和姿态误差确实回退，当前不主张真人泛化全面改善。系统最明确的增益在机器人域，真人DEV有改善。DEV以较长移动动作居多，VAL短时上肢/静态动作较多；这种分布差异值得分动作检查，但不能只凭均值确定回退原因。

**Q：scale改善有多稳？**

A：同24k、同seed无残差对照中，真人VAL q从.1198→.1075→.0971rad，48→256约下降18.95%；DEV root/yaw非单调，机器人VAL规模曲线尚未完整注册。256段来自27条原录制、约17.4分钟teacher支持，不是数小时新场景，也不是统计上256个独立采集单位。

**Q：到底会不会跳？高接触F1是不是已经证明了？**

A：固定8条真人困难动作里的6条跳跃/开合跳，teacher与学生均没有持续≥50ms有效腾空，所以不能报告跳跃成功。接触F1高可以来自双方都在地面。LAFAN独立teacher有腾空的7个DEV窗口上，再查询的最终腾空IoU也只有.061；必须以实际接触、腾空持续时间和目标时序评价事件。

**Q：困难动作视频和评分是不是截断的？**

A：8条真人学生执行完整输入，共38.34秒控制；teacher和机器人输入受未来参考支持约束为30.86秒。已明确标出无支持尾部，那里不评分。困难训练的11/11完成也指共同有效前缀，不能写成全部128秒原请求执行完成。

**Q：状态再查询为什么有效，又为什么oracle没有全面更好？**

A：相对BC，实际student状态上的再查询与事件加权改善姿态及接触。但标签重查目前主要使用当前yaw，不是根据全部状态求恢复专家；额外速度/接触有信号、有梯度，也不自动创造更好的纠偏目标。这是机制解释而非单seed因果证明。oracle读取仿真真实量，应标成信息上界实验，不是已部署视觉估计器。

**Q：纠偏探针是不是RL成果？**

A：不是。6个TRAIN状态、78个合法候选，逐候选进行1秒真实物理执行；固定综合目标下q和速度改善，但XY略增。候选含teacher特权提案，没有蒸馏新策略或独立泛化验证，支持的是命令空间存在局部纠偏余地。

**Q：部署时需要逐视频retarget吗？整个系统实时吗？**

A：当前学习接口推理直接从RGB估计运动并预测SONIC命令，不调用逐视频显式机器人retarget或reference encoder；训练标签制作仍使用已有参考与teacher链。当前GV整段推理和+0.5s窗口是离线模式；缓存映射很快、低层50Hz和端到端在线实时是不同命题。

**Q：0.63秒能否称为端到端实时？从29.88秒到0.63秒是不是几十倍加速？**

A：0.63秒是常驻完整视觉前端的服务时间，不含命令头和机器人执行；约1.6Hz尚未达到10Hz新视觉命令目标。29.88秒是每项重新启动、长度不同的冷前缀处理，两种协议不能相除作为系统加速比。完整摄像头RGB到首次实际动作尚无统一时钟实测。

**Q：流式学生已经完成了吗？**

A：尚未实现。已经完成的过去窗口适配仍以GV输出145维几何为输入；计划中的逐帧视觉＋GRU/因果TCN学生需要独立训练、执行质量与端到端计时证据。

**Q：新的15.5秒动作是外部真人泛化吗？**

A：它来自LAFAN机器人渲染DEV，是本周R46状态再查询的局部对照。外部真人HuMMan仍展示旧R38 F48的4.40秒与2.92秒示例；本周没有已证优于旧示例的新外部真人执行demo。
